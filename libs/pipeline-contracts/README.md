# Pipeline contracts

Pure validation and payload construction for the gateway and future service consumers. This library performs no rule matching, spatial indexing, geometry intersections, network calls, or message delivery. Algo converts the original rule geometry from GeoJSON to WKT.

`PipelineContractRegistry` resolves explicitly registered contract IDs using ordinal comparison. Unknown IDs fail resolution. The gateway registers `AsdPipelineContract` as `asd` and `AlgoPipelineContract` as `algo`. Pipeline contracts use unversioned IDs.

One ASD run-parameter object describes one tenant dispatch:

```json
{
  "tenantId": "tenant-a",
  "algorithmNames": ["FindAir", "Rpn"],
  "tilingConfigs": [
    {
      "tileSizeWidth": 500,
      "tileSizeHeight": 500,
      "tileOverlapWidth": 10,
      "tileOverlapHeight": 10
    }
  ]
}
```

All shown fields are required. Unknown or duplicate properties, empty collections, duplicate/unsupported algorithm names, numeric strings, and invalid tiling dimensions are rejected. Zero overlap is valid. Algorithm parsing and tiling validation reuse the common DTO contracts.

`ValidateRunParams`, `ValidateExtraData` and `ValidateContext` return field-level errors. `BuildPayload` validates its inputs again and throws `ArgumentException` on failure. Each contract validates only its own required event data. Contexts contain a caller-assigned task identity; the caller must keep their `JsonElement` alive while calling the contract (or supply a clone).

`OverlayDispatchContextFactory.Create(taskId, ruleId, overlay)` projects the flat update-overlay JSON (`id`, `photoTime`, `roiFootprint`, and other fields) into the shared context. It never substitutes `footprint` for `roiFootprint`. Algo does not require ASD's image dimensions, image URL or grid URI. Missing ASD values are rejected by ASD's context validation. This projection is a payload-building helper; it does not consume messages, match rules or decide the selected ROI for ASD.

The ASD payload preserves the existing gateway's ordered JSON body, including singular `algorithmName` as an array and exact `gridURI` spelling. All tiling configurations remain in that tenant's body. Attributes are `algorithmName` (comma-joined names) and `tenantId`; these describe metadata for protocol adapters. Task IDs are supplied by the caller, not generated by the contract.

`PipelinePayload` also has optional typed `RabbitMqAttributes`. ASD supplies `findair-contract-version` as an **integer** with value `1` in this dictionary to preserve the existing downstream wire contract. This marker is independent of unversioned pipeline and contract IDs. These attributes are contract output only; the library does not execute transport mapping or delivery.

`BuildPayload` accepts per-pipeline `extraData` as a JSON object of contract settings. Each contract defines its interpretation. ASD retains its existing behavior: it includes nonempty data under the body's `extraData` property, preserving names and JSON types. It cannot override existing body fields or headers. Omitting the object or supplying `{}` preserves the existing ASD payload shape.

## Algo

One Algo run-parameter object describes one selected rule's mission request:

```json
{
  "customer": "replace-me-customer",
  "profile_name": "replace-me-profile",
  "hebrew_rule_name": "replace-me-mission",
  "algorithm_name": "replace-me-algorithm",
  "priority": 1,
  "username": null,
  "run_every_other_image": false,
  "should_check_in_vip": false,
  "location_geojson": {
    "type": "Polygon",
    "coordinates": [[[0, 0], [2, 0], [2, 2], [0, 0]]]
  }
}
```

The optional `profile_name`, `hebrew_rule_name` and `username` accept strings or null. The other fields are required, with the shown JSON types. `algorithm_name` is one string and does not use ASD's algorithm enum. `priority` is a 32-bit integer without an invented business range. Unknown and duplicate run parameters, malformed geometry, and empty geometry are rejected. These are the payload-relevant fields, not the entire stored rule document: matching conditions and rule metadata remain outside this contract.

Configure each Algo pipeline's `ExtraData` with:

```json
{
  "XUserName": "replace-me-user",
  "Origin": "replace-me-origin",
  "QueueType": "replace-me-queue-type",
  "SaveDetections": true
}
```

All four settings are required with nonempty strings and a JSON boolean. Unknown extra settings are allowed and ignored; they cannot override other output fields or create a nested `extraData` property. Duplicate recognized settings are rejected. Two pipelines may use the same `algo` contract with different settings.

The body follows the supplied Algo Manager builder: `customer` supplies `requestingUnit` and `displayName`; `profile_name` supplies `modelName`; `username` falls back to `XUserName` only when null. `missionName` combines the rule's Hebrew name with the image date formatted `dd/MM/yyyy` using invariant culture. The original `location_geojson` supplies `focusedWkt`, independently of the input ROI. `origin`, `queueType` and `saveDetections` come from `ExtraData`.

`tasksData` contains one task with `imageId`. When `run_every_other_image` is true, its nullable `legId`, `prevOverlayId` and `nextOverlayId` come from the overlay. When `should_check_in_vip` is true, `photoTime` is assigned. Unassigned nullable properties are serialized as null. These flags describe downstream behavior; the builder does not perform alternating-image filtering or VIP checks.

The factory stores the photographed legacy `DateTime.Parse(..., InvariantCulture)` result as `OverlayPhotoTime`, independently of the UTC `PhotoTime` used by ASD. Algo prefers that legacy clock value and otherwise uses `PhotoTime.DateTime` without another UTC conversion. Offset-bearing input follows the legacy process timezone when parsed; matching the old deployment's timezone preserves its calendar-day behavior. A null Hebrew rule name retains the legacy leading-space mission name rather than inventing a fallback.

Roberto, warmup, HTTP status handling, retries, rule snapshots and dispatch are outside this library. The contract prepares bytes only.
