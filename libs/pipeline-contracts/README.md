# Pipeline contracts

Pure validation and payload construction shared by the gateway and rules API. This library performs no rule matching, geometry calculation, network calls, or message delivery.

`PipelineContractRegistry` resolves explicitly registered contract IDs using ordinal comparison. Unknown IDs fail resolution. Register `AsdPipelineContract` as `asd`; an Algo contract requires its actual downstream schema before registration. Pipeline contracts currently use unversioned IDs.

One ASD run-parameter object describes one tenant dispatch:

```json
{
  "tenantId": "tenant-a",
  "algorithmNames": ["FindAir", "Rpn"],
  "tilingConfigs": [
    {
      "tileSizeWidth": 500,
      "tileSizeHeight": 500,
      "tileOverlapWidth": 10,
      "tileOverlapHeight": 10
    }
  ]
}
```

All shown fields are required. Unknown or duplicate properties, empty collections, duplicate/unsupported algorithm names, numeric strings, and invalid tiling dimensions are rejected. Zero overlap is valid. Algorithm parsing and tiling validation reuse the common DTO contracts.

`ValidateRunParams` returns field-level errors. `BuildPayload` validates the same parameters and throws `ArgumentException` on failure. Its context carries an already validated event, the selected ROI as a GeoJSON object, and a caller-assigned task identity. The caller owns event/geometry validation and must keep the `JsonElement` alive while calling the contract (or supply a clone).

The ASD payload preserves the existing gateway's ordered JSON body, including singular `algorithmName` as an array and exact `gridURI` spelling. All tiling configurations remain in that tenant's body. Attributes are `algorithmName` (comma-joined names) and `tenantId`; these describe metadata for protocol adapters. Task IDs are supplied by the caller, not generated by the contract.

`PipelinePayload` also has optional typed `RabbitMqAttributes`. ASD supplies `findair-contract-version` as an **integer** with value `1` in this dictionary to preserve the existing downstream wire contract. This marker is independent of unversioned pipeline and contract IDs. These attributes are contract output only; the library does not execute transport mapping or delivery.

`BuildPayload` accepts optional per-pipeline `extraData` as a JSON object. ASD includes nonempty data under the body's `extraData` property, preserving its names and JSON types. It cannot override existing body fields or headers. Omitting the object or supplying `{}` preserves the existing ASD payload shape.
